## Локальный запуск

1. Создайте ветку `review`: `git switch -c review`.
2. Создайте `.env`, `backend/.env` и `frontend/.env` из соответствующих `.env.example`. Установите в корневом `.env` надёжный `MONGO_ROOT_PASSWORD`.
3. В `backend/.env` установите `DB_ADDRESS=mongodb://root:<пароль-из-корневого-.env>@mongo:27017/weblarek?authSource=admin`, заполните **уникальные** секреты `AUTH_ACCESS_TOKEN_SECRET`, `AUTH_REFRESH_TOKEN_SECRET`, `ORIGIN_ALLOW=http://localhost`, `COOKIE_SECURE=false`.
4. MongoDB получает имя пользователя и пароль из корневого `.env`. Не публикуйте этот файл и не открывайте порт БД в интернет.
5. Запустите `docker compose up -d --build`.
6. Импортируйте данные по инструкции [`.dump/README.md`](.dump/README.md). **Тестовые пользователи из дампа содержат старые MD5-хеши**: после исправления хеширования они не смогут войти. Зарегистрируйте новых пользователей, а тестовому администратору назначьте роль `admin` напрямую в локальной БД.
7. Откройте http://localhost/ (витрина), http://localhost/login/ (вход), http://localhost/admin/ (админка).

## Безопасность

- XSS: комментарии показываются как обычный текст, а не вставляются в DOM как HTML.
- CSRF: `POST /auth/token` и `POST /auth/logout` требуют `X-CSRF-Token`. Токен устанавливается при успешном входе и привязан к refresh-cookie посредством HMAC.
- NoSQL-инъекции: фильтры и поля обновления ограничены; произвольные поля и MongoDB-операторы не должны попадать из пользовательского запроса в запрос к базе.
- ReDoS: поиск экранируется; ограничена длина строк; упрощено выражение для телефона.
- Загрузка: случайные имена, лимит 5 МиБ, PNG/JPEG/GIF с проверкой сигнатур, SVG запрещён.
- DDoS: ограничены размер запросов, частота запросов к API и логирование.
- Path traversal: используются `express.static` и ограниченные пути к загруженным файлам.
- Пароли: вместо MD5 используется bcrypt. Старые тестовые хеши автоматически не мигрируются.

**Внимание:** это локальная учебная конфигурация. Не выкладывайте тестовые пароли и MongoDB-порт в интернет. Полная защита от распределённых DDoS-атак требует дополнительных средств уровня инфраструктуры.

## Нагрузочные тесты (только свой локальный сервис)

Прежде чем повышать конкурентность, проверьте `docker stats`, `docker compose logs --tail 100` и свободное место `df -h`. Начните с умеренной нагрузки:

```bash
ab -k -c 10 -n 1000 http://localhost/
```

Не направляйте нагрузочное тестирование на чужие или общедоступные сервисы без разрешения.
